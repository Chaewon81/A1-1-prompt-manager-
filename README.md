# 🗂️ Prompt Manager

Python으로 만든 **개인 프롬프트 관리 콘솔 프로그램**입니다.

자주 사용하는 AI 프롬프트를 카테고리별로 관리하고, 키워드 검색과 상세 조회, 즐겨찾기 기능을 통해 원하는 프롬프트를 빠르게 찾을 수 있도록 제작했습니다.

---

## 📌 프로젝트 목적

AI를 학습하고 활용하면서 반복적으로 사용하는 프롬프트를 체계적으로 관리하기 위해 개발한 Python 기반 콘솔 프로그램입니다.

Python의 기본 문법과 자료구조를 활용하고, Git을 이용하여 기능 단위로 개발 및 버전 관리를 진행하는 것을 목표로 했습니다.

---

* 프롬프트 추가

* 카테고리별 조회
* 프롬프트 검색

* 메뉴 기반 콘솔 인터페이스

## 🔎 검색 기능

프롬프트의 **제목과 내용**을 대상으로 키워드 검색을 수행합니다.

예를 들어:

```text
검색할 키워드를 입력하세요: 영어
```

결과:

```text
1 ☆ 영어회화 선생님 [ 텍스트 생성 ]
```

### 검색 방식

현재 검색은 Python의 문자열 `in` 연산자를 이용한 **부분 문자열 검색** 방식입니다.

```python
if keyword in prompt["title"] or keyword in prompt["content"]:
```

프롬프트가 `N`개라면 한 번의 검색에서 각 프롬프트를 순차적으로 확인하므로 기본적인 시간 복잡도는 **O(N)**입니다.

### 검색의 한계

* 현재는 단순 문자열 검색 방식입니다.
* 형태소 분석이나 검색어 추천 기능은 제공하지 않습니다.
* 대소문자 구분이 필요한 데이터의 경우 검색 결과가 달라질 수 있습니다.

향후에는 검색어를 소문자 또는 대문자로 통일하여 비교하는 방식으로 개선할 수 있습니다.

```python
prompts[index]["favorite"] = not prompts[index]["favorite"]
```

## 🗃️ 데이터 구조

프롬프트 데이터는 Python의 **리스트(List)와 딕셔너리(Dictionary)**를 조합하여 관리합니다.

예:

```python
{
    "title": "영어회화 선생님",
    "content": "너는 영어회화 전문 선생님이야.",
    "category": "텍스트 생성",
    "favorite": False
}
```

### 필드 설명

| 필드         | 타입   | 설명        |
| ---------- | ---- | --------- |
| `title`    | str  | 프롬프트 제목   |
| `content`  | str  | 프롬프트 내용   |
| `category` | str  | 프롬프트 카테고리 |
| `favorite` | bool | 즐겨찾기 여부   |

### 자료구조를 선택한 이유

프롬프트 전체를 관리하기 위해 `list`를 사용하고, 각각의 프롬프트를 여러 속성을 가진 하나의 데이터 객체처럼 표현하기 위해 `dict`를 사용했습니다.

이 구조는 Python의 기본 자료구조만으로 구현할 수 있어 학습 목적의 프로젝트에 적합하며, 데이터의 추가와 순차적인 조회가 간단하다는 장점이 있습니다.

반면 데이터가 많아질 경우 검색 성능이 떨어질 수 있고, 프로그램을 종료하면 메모리에 저장된 데이터가 사라진다는 한계가 있습니다.

향후 데이터 규모가 커질 경우 JSON 또는 SQLite 기반 저장 구조로 확장할 수 있습니다.

## 🧱 함수 설계

프로그램은 기능별로 함수를 분리하여 각 함수가 하나의 주요 책임을 담당하도록 구성했습니다.

| 함수                   | 역할                |
| -------------------- | ----------------- |
| `show_menu()`        | 메인 메뉴 출력          |
| `show_prompts()`     | 전체 프롬프트 목록 출력     |
| `add_prompt()`       | 새로운 프롬프트 추가       |
| `show_by_category()` | 카테고리별 프롬프트 조회     |
| `search_prompts()`   | 제목과 내용 기반 검색      |
| `show_detail()`      | 선택한 프롬프트 상세 정보 출력 |
| `manage_favorites()` | 즐겨찾기 관리 메뉴 제공     |
| `toggle_favorite()`  | 즐겨찾기 상태 변경        |
| `show_favorites()`   | 즐겨찾기 목록 출력        |

### 호출 흐름

전체적인 프로그램 흐름은 다음과 같습니다.

```text
프로그램 시작
      ↓
기본 프롬프트 데이터 로드
      ↓
메인 메뉴 출력
      ↓
사용자 메뉴 선택
      ↓
선택한 기능 실행
      ↓
다시 메인 메뉴 출력
      ↓
0 선택
      ↓
프로그램 종료
```

## 🔁 메인 반복문 설계

프로그램은 사용자가 종료 메뉴인 `0`을 선택할 때까지 반복적으로 메뉴를 제공합니다.

반복문을 사용하는 이유는 하나의 실행 과정에서 프롬프트 추가, 검색, 상세 조회, 즐겨찾기 관리 등의 여러 기능을 연속적으로 사용할 수 있도록 하기 위해서입니다.

종료 조건은 사용자가 메뉴에서 `0`을 선택하는 것입니다.

```text
while 반복
    ↓
메뉴 출력
    ↓
사용자 입력
    ↓
기능 실행
    ↓
0이면 종료
    ↓
그 외에는 다시 메뉴 출력
```

## ✅ 입력 검증

사용자 입력에 대해 기본적인 검증을 수행합니다.

예:

* 제목 빈 값 방지
* 내용 빈 값 방지

예를 들어 카테고리 선택에서 잘못된 번호를 입력하면:

```text
카테고리 번호를 입력하세요: 0
잘못된 번호입니다.
```

와 같이 안내합니다.

향후에는 반복되는 입력 검증 로직을 별도의 공통 함수로 분리하여 코드 중복을 줄일 수 있습니다.

## 🏷️ 중복 데이터 처리 정책

현재 프로그램은 동일한 제목의 프롬프트를 별도의 항목으로 저장할 수 있습니다.

따라서 제목이 같더라도 내용이나 카테고리가 다른 프롬프트를 각각 저장할 수 있습니다.

현재는 별도의 UUID를 사용하지 않고 **리스트의 인덱스를 프롬프트 번호로 사용**합니다.

향후 데이터가 증가하면 각 프롬프트에 고유 ID를 부여하여 제목이 같은 프롬프트도 안정적으로 관리할 수 있도록 개선할 수 있습니다.

## 💾 데이터 영속화 설계

현재 버전은 프로그램 실행 중 메모리에서 프롬프트 데이터를 관리합니다.

따라서 프로그램을 종료하면 실행 중 추가한 프롬프트와 변경한 즐겨찾기 상태가 초기화됩니다.

### 향후 영속화 방식

향후에는 **JSON 파일 저장 방식**을 우선적으로 적용할 예정입니다.

예상 구조:

```text
prompt_manager.py
prompts.json
README.md
```

JSON을 선택한 이유:

* Python에서 기본적으로 지원하는 `json` 모듈을 사용할 수 있음
* 리스트와 딕셔너리 구조를 그대로 저장하기 쉬움
* 별도의 데이터베이스 설치가 필요 없음
* 학습용 개인 프로그램에 적합함

### JSON 방식의 한계

데이터가 매우 많아질 경우 전체 파일을 읽고 저장해야 하므로 성능이 떨어질 수 있습니다.

향후 사용자 수나 데이터 규모가 증가하면 SQLite 등의 데이터베이스를 사용할 수 있습니다.

현재 버전은 Python과 Git의 기본 기능 학습을 목적으로 제작되었습니다.

향후 다음 기능을 추가할 수 있습니다.

1. JSON 파일을 이용한 데이터 영속화
2. 프롬프트 수정 및 삭제
3. 대소문자를 구분하지 않는 검색
4. 고유 ID 기반 프롬프트 관리
5. 공통 입력 검증 함수 도입
6. SQLite 데이터베이스 연동
7. 검색 결과 정렬 기능
8. 프롬프트 태그 기능
9. GUI 또는 웹 인터페이스 추가

---

## 📌 프로젝트 한계

현재 프로그램은 학습용 콘솔 프로그램이므로 다음과 같은 한계가 있습니다.

* 프로그램 종료 시 데이터가 초기화됨
* 데이터가 많아지면 리스트 기반 검색 성능이 떨어질 수 있음
* 검색 기능이 단순 문자열 검색 방식임
* 사용자 인증 기능이 없음
* 데이터베이스를 사용하지 않음

이러한 한계는 향후 JSON 또는 SQLite를 이용한 영속화와 검색 기능 개선을 통해 해결할 수 있습니다.
